## Why

After the first live billing run (42 cards charged ✅), 3 rows confused the owner: retrying them showed "Sent email / 0 charged" with no explanation. Cause: those clients' saved cards predate the Oct 1 surcharge rule and have no billing ZIP — unchargeable, so the run correctly fell back to emailing the invoice. But the board rendered a plain green "sent" badge and swallowed the reason.

## What

- `savedCard.needsZip` exposed in invoicesData (adds `run_card_zip` to the customers select)
- Billing run board: amber **⚠ brand ••last4 · needs ZIP** row badges before the run, amber **needs ZIP — sent instead** result badges after, a `· N need ZIP ⚠` note on the Card-on-file summary chip, and a separate line in the run-confirm dialog
- `billing_run` marks those rows `warn: "card_missing_zip"` (data-driven, not string-matching)

Customer comms: texts sent to the 3 affected clients (Lucy Bui, Ian Rent Jax, Bee Clean 360) explaining the processor now requires the billing ZIP and linking their portal to re-save — sender "Valet Waste Team".

## Validation

- `npm run build` ✅
- `deno check` on the payments fn: same 7 pre-existing errors as main, zero new.
